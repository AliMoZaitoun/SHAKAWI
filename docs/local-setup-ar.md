# تشغيل نسخة الكود على جهازك

**واجهة React الجديدة:** بعد clone/pull، اقرأ `docs/react-frontend-ar.md`؛
تحتاج تثبيت حزم Node وتشغيل `pnpm build` قبل تشغيل النسخة الجديدة على 5000.
الأوامر أدناه لتجهيز Python والبيئة تبقى صحيحة.

## مهم قبل البداية

ZIP يحتوي الكود والتوثيق والاختبارات فقط؛ لا يحتوي .env أو قاعدة البيانات أو صور المواطنين. لا تضعه فوق نسختك الوحيدة ولا تستبدل بياناتك القديمة. فكّه في مجلد جديد أولاً، وخذ نسخة خاصة من قاعدة بياناتك وuploads مع إيقاف الموقع والبوت.

استخدم Python 3.12 الموصى به للمشروع. ثبّت الحزم بنفس Python الذي ستشغّل به:

```bash
python -m pip install -r requirements.txt
```

## إعداد البيئة

لنسخة جديدة فقط، انسخ .env.example إلى .env محلياً. إذا عندك .env شغال، احتفظ فيه ولا تستبدله.

اضبط SESSION_SECRET لقيمة عشوائية خاصة وثابتة، ويمكنك توليدها على جهازك:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

ضع الناتج عندك في .env ولا ترسله بالمحادثة ولا ترفعه إلى GitHub. هذا مفتاح جلسات الخادم، وليس مفتاح استعادة المواطن.

تأكد من:

```dotenv
API_BASE_URL=http://127.0.0.1:5000/api/v1
SHAKWA_DATABASE_URL=sqlite:///./gov_complaints.db
APP_ENV=development
ENABLE_DEMO_ACCOUNTS=0
```

BOT_TOKEN اختياري لتشغيل البوت، وبدونه الموقع يعمل وحده. إذا شغلت البوت على جهازك أوقف النسخة الأخرى من polling لنفس البوت.

على أي قاعدة لا تحتوي حساب system_admin يجب ضبط SYSTEM_ADMIN_PASSWORD لكلمة خاصة بطول 12 حرفاً على الأقل؛ ينشئ ذلك حساباً منفصلاً عن المحافظ، ولا توجد له كلمة مرور افتراضية أو تجريبية. يمكن ضبط GOVERNOR_PASSWORD وSERVICES_PASSWORD، أو تفعيل ENABLE_DEMO_ACCOUNTS=1 للاختبار المحلي الاصطناعي لحسابي governor وservices فقط. الوضع التجريبي ينشئهما بكلمة 123456 إذا لم يكونا موجودين ولا يغير كلمة حساب موجود. لا تستخدمه مع بيانات حقيقية أو في الإنتاج.

## الترحيل والتشغيل

إذا تريد بياناتك المحلية القديمة: انسخ نسخة خاصة منها ومن uploads إلى مجلد العمل الجديد قبل الترقية، بعد حفظ الأصل وإيقاف كل الكتّاب. لا تضع هذه الملفات على GitHub.

من جذر المشروع:

```bash
python -m dotenv -f .env run -- python -m app.db.upgrade
python -m dotenv -f .env run -- python run.py
```

الرابط المحلي:

```text
http://127.0.0.1:5000/
http://127.0.0.1:5000/docs
```

التطبيق لا يقرأ .env ضمنياً. الأمر أعلاه يحمله صراحة. وجود API_BASE_URL الصحيح يمنع رجوع البوت إلى منفذ قديم. لا تشغل python -m bot.main بالتوازي مع run.py الذي شغّل البوت بالفعل.

لـSwagger: نفّذ POST /api/v1/auth/login، بعدها الطلبات من نفس المتصفح تستخدم جلسة الكوكيز. لا يوجد Bearer token مطلوب لحساب الموظف الحالي. استخدم مسارات admin لإسناد الصلاحيات، ولا تعدّل جدول الموظف القديم لتمنح دوراً.

## الاختبارات

```bash
python -m pip install -r requirements-dev.txt
python -m dotenv -f .env run -- python -m pytest tests/ -q
```

الاختبارات تستخدم قواعد منفصلة وبيانات اصطناعية؛ لا تُشغّل تجارب يدوية على بيانات مواطنين حقيقيين.

اختبارات المتصفح الاختيارية تحتاج Playwright ومتصفح Chromium متاحاً؛ اقرأ متطلبات جهازك قبل تشغيلها. تم التحقق منها في بيئة التطوير. اختبار تيليغرام الآلي يستخدم محاكاة واتصالات API موثقة، وليس إثبات وصول رسالة حقيقية إلى تيليغرام.

## الملفات التي تحتاج قراءتها أولاً

1. docs/database-foundations-ar.md: الجداول واللغات والملفات والتدقيق والنسخ الاحتياطي.
2. docs/identity-rbac.md: الأدوار والنطاقات وإدارة الموظفين.
3. app/main.py: تجميع المسارات وبدء التشغيل.
4. migrations/versions/: تاريخ الترحيلات.

تغيير ملفات الكود لا يحدث نسخة ZIP القديمة تلقائياً؛ نزّل النسخة الجديدة التي سُلّمت مع هذه المرحلة.
